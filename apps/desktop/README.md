# Avero Desktop Workbench (`apps/desktop`)

Desktop shell for AveroDisassembler: **Tauri 2 + Vite 5 + React 19 + TypeScript strict**.
The **Avero core (Rust)** is linked into the executable and its REST/SSE API runs on a
background thread inside the app process — no Node runtime and **no separate server to run**
(WebView2 on Windows).

## Features

- **File mode (offline)** — open an `avero.report/v1` `report.json`, attach the original
  artifact for hex inspection, recent-report cache in `localStorage`.
- **API mode (default)** — talks to the **embedded core API** (`avero.api/v1`) started automatically:
  health badge, artifact scan with SSE progress, report fetch by id, paged string search,
  hex slices, rizin disassembly, ILSpyCmd/Ghidra decompile jobs with SSE progress,
  engine list/install, report diff and APK/.NET/signature facts.
- Screens: Home, Overview, Findings (with evidence), Evidence, Sections, Imports/Exports,
  Strings, **editable hex editor** (byte patches + patched-copy export), APK Manifest,
  .NET Metadata, Signatures, **Functions & Map** (rename/comment/prototype annotations,
  callers/callees, clickable SVG call graph), **Disassembly** with cross-reference jumps,
  Decompile, Diff, Engine packs, Settings.
- Static-only, read-only, evidence-first: the artifact is never executed.

## Prerequisites

- Rust stable + MSVC build tools (Windows) / `libwebkit2gtk` (Linux, if built there)
- Node 20+ and pnpm
- WebView2 runtime (preinstalled on Windows 11)
- no external server required (the core is bundled). Optional: an external `avero serve` can be used via Settings for development.

## Development

```powershell
pnpm install
pnpm --filter desktop typecheck
pnpm --filter desktop build            # vite production assets
pnpm --filter desktop tauri dev        # Tauri dev window (Vite dev server)
```

On Windows, run from a shell that has the MSVC environment (or use
`scripts\build.bat` for the core; Tauri build needs `vcvars64.bat`):

```powershell
cmd /c "call \"C:\Program Files\Microsoft Visual Studio\18\Community\VC\Auxiliary\Build\vcvars64.bat\" && pnpm --filter desktop tauri build --no-bundle"
```

The executable is written to `src-tauri/target/release/avero-desktop.exe`.

## Embedded core

The app links the `avero` core crate and starts its loopback REST/SSE API on a random free port
at launch (the UI receives the URL through the `api_base_url` Tauri command). The core
working directory is the per-user app-data directory (`%APPDATA%\\com.avero.workbench`),
which also holds seeded engine manifests and installed engines — no Program Files writes.

Health, scans, decompile and engine install all flow through this embedded API. An external
`avero serve` remains supported via Settings for browser/CLI development.

## Analysis workspace (Ghidra/IDA-style)

- `Functions & Map`: embedded core runs rizin `aaa` + `aflj`; the UI lists functions,
  persists local annotations (name/comment/prototype) per artifact in `localStorage`,
  shows callers/callees and an interactive SVG call graph (click a node to jump).
- `Disassembly`: address/limit form, clickable function-start addresses and `call` targets;
  annotated names are resolved in operands; nearby-function list for quick navigation.
- `Hex editor`: click any byte, type a hex value and Apply; edited bytes are highlighted;
  `Export patched copy` downloads `<artifact>.patched` (full artifact + local patches).
- Core endpoints used: `/api/reports/{id}/functions`, `/api/reports/{id}/artifact`, plus the
  existing disassembly/hex/report endpoints.

## Notes / limits
- Native `<button>` appearance is reset globally so the dark sidebar stays dark in WebView2
  (no white UA button backgrounds); child processes use `CREATE_NO_WINDOW` so engine
  install/decompile/disassembly never flash cmd windows.

- The desktop shell reuses the same API/data contracts as the web UI but is a standalone
  Vite app (no Next.js runtime).
- Monaco is not bundled; decompiled code uses a read-only `<pre>` viewer with copy.
- Installers (`msi`/`nsis`) are not built by default (`--no-bundle`); add a bundler target
  when shipping.
- Build artifacts (`dist/`, `src-tauri/target/`, generated schemas) are git-ignored.
