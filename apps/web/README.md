# AveroDisassembler Web Workbench (`apps/web`)

## 1. Overview & Purpose

The **AveroDisassembler Web Workbench** is an evidence-first, static-only reverse-engineering report explorer built with **Next.js 15 (App Router)**, **React 19**, **TypeScript** (strict mode), and **Tailwind CSS**.

It serves as the human-in-the-loop triage interface for static analysis reports produced by the Avero core engine (`avero`). Conforming strictly to contract specification `avero.report/v1` and API specification `avero.api/v1` (detailed in `docs/UI-SPEC.md`), the workbench operates under core architectural principles:
- **Evidence-First**: Every security or structural finding links directly to verifiable byte or metadata locators.
- **Strictly Read-Only**: The UI never performs live binary execution, disassembly patching, or symbol mutations.
- **Local-First & Offline Capable**: In File Mode (M1), reports and binaries are processed purely in client-side memory without external network calls.
- **Virtualized High Performance**: Virtualized lists handle 100k+ extracted strings and paged hex byte slices at 60 fps.

## 2. Prerequisites & Dependencies

### Runtime Requirements
- **Node.js**: `v20.0.0` or higher (verified on `v22.22.0`).
- **Package Manager**: `pnpm` (v9 or v10+; install via `npm install -g pnpm` or `corepack enable pnpm`).
- **Browser**: Modern Chromium, Firefox, or WebKit browser supporting ES2022 and CSS Variables.

### Key Dependencies
- `next`: `^15.1.0` (App Router, Server & Client Components)
- `react`, `react-dom`: `^19.0.0`
- `@tanstack/react-virtual`: `^3.11.0` (Virtual scrolling for strings and tables)
- `lucide-react`: `^0.469.0` (Icons)
- `tailwindcss`: `^3.4.16` with design tokens
- `vitest`: `^2.1.8` + `@testing-library/react` (Unit and component tests)

## 4. Usage Examples

### 4.1 Development Server
```bash
# From workspace root
pnpm --filter web dev

# Or directly inside apps/web
cd apps/web
pnpm dev
```
Open [http://localhost:3000](http://localhost:3000) in your browser.

### 4.2 Running Tests
```bash
# Run all unit and component tests
pnpm --filter web test
```

### 4.3 Building for Production
```bash
pnpm --filter web build
```

### 4.4 Opening a Report (File Mode)
1. Navigate to `http://localhost:3000`.
2. Drag and drop any `report.json` generated by `avero scan <file> --json` (or click **"Open Sample Report"** to explore `docs/api/sample-report.json`).
3. Explore the Triage Overview, Findings Drawer, Evidence Locators, Entropy Bars, Virtualized Strings, and Hex Viewer.

## 6. Troubleshooting & Edge Cases

| Issue / Symptom | Root Cause | Solution |
|---|---|---|
| `pnpm approve-builds` error during install | pnpm v10+ requires script approval for native packages (e.g. `esbuild`) | Run `pnpm approve-builds --all` once |
| "Artifact Bytes Required" in Hex Viewer | Report JSON only stores offsets and triage metadata; raw binary bytes were not attached | Click "Provide Original Artifact File" in the Hex Viewer to select the target binary |
| Large report (>50MB) sluggishness | Parsing huge JSON files on the main UI thread | Ensure the browser tab has sufficient memory; recent reports are capped at 10 items in `localStorage` |
| Route not updating on browser back | Dynamic route cache | Next.js App Router synchronizes query parameters via `useSearchParams()` |
